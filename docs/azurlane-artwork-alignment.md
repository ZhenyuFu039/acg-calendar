# 碧蓝航线头图自动对齐（未发布）

新增的是现有 `azurlane-wiki` 引擎中的媒体补全功能，插件 API 仍为 1。日历仍从 BWIKI 国服改建公告提取；英文 Wiki 仅提供图片候选和对照证据，绝不修改国服起止、预计状态和提醒时刻。无需 AI API。

## 国服公告主视觉兜底

当前源码进一步支持 `rules.json.bulletin_artwork`：扫描国服公告末尾 `From 司令部` 后的图片引用，只在找到唯一且文件名对应本篇活动名称的素材时，通过 Wiki `imageinfo` 查询真实 CDN 地址。检查宽度至少 400、横图比例 1.2–4、大小不超过 5 MB，并沿用已有的图片类型和来源检查。

已识别的独立活动头图优先；没有独立图的条目使用它所属公告的主视觉，明确标注“共用主视觉”，不是将其认作该活动的独立宣传图。只按 `evidence.page_title` 绑定，不根据相近日期跨公告继承；商店与领取的起止仍分别保留。

用户指定的 [2026-10-22 改建公告 · 修订 418469](https://wiki.biligame.com/blhx/index.php?title=2026%E5%B9%B410%E6%9C%8822%E6%97%A510%3A00%E6%B8%AF%E5%8C%BA%E6%94%B9%E5%BB%BA&oldid=418469)末尾引用 `飓风与雾霭回廊.jpg`，公开图片接口返回 1920×1080 的 JPG。该公告解析出的 5 条记录均已验证可使用：飓风与雾霭回廊、活动商店、累计奖励领取、港区假日故事集 光与暗的邀约、限界挑战：天蝎座。公告与图片元数据样本保存在 `samples/azurlane-cn-20261022*.json`，元数据缓存为 `sources/cn-bulletin-artwork.json`。

单轮最多追加一批图片元数据查询，已有缓存不再查询同一文件，同图只下载一次。接口不可用、图片非横图、多个候选或公告没有主视觉时保留原图片/无图状态，不阻断国服时间数据。

## JSON 负责什么

[`artwork-alignment.json`](../plugins/azurlane-cn/artwork-alignment.json) 声明更新目录中的活动标题前缀、采集上限、头图文件名规律、中文/英文名称别名、奖励对象词典、任务正则、结构分类、日期容差和分数门槛。名称别名是人工整理的知识；不是自动翻译。新任务句式和新名称可能仍需补充 JSON，但不再需要为每个已能识别的活动填写图片 URL。

流程如下：

1. 通过公开 MediaWiki `action=parse` 接口读取 Recent News，只从近 60 天的更新批次中的活动标题发现候选专题，不遍历角色、换装或所有站内链接。每轮最多读取 6 个专题，在候选池内优先检查未缓存/较久未检查的页面。
2. 从专题各自的日期表取头图及日期，分别保留 EN / All Servers 的首次开放和复刻记录。同页多张图片没有各自日期时，不把主活动日期套给其他图片。
3. 使用名称别名、任务指纹或至少两个奖励对象作为独立身份依据。根据可靠锚点为每篇国服改建公告单独推断“国服活动日期－外服活动日期”的偏移，最多允许 21 天。锚点冲突则该批次放弃自动匹配，不推导一个适用于所有版本的固定差值。
4. 开始日期对齐后需一致，结束日期默认允许 1 天差异，兼容“国服次日维护前”和外服前一天结束的日期表达。**这只是图片候选容差，不是修改日历时间。** 还必须有独立身份依据，默认总分至少 85，第一与第二候选至少相差 15 分。
5. 同一张图被两个独立国服活动争用时，两者均放弃自动分配。只有显式 `parent_id` 的商店、领取子项可以继承父活动头图；仍保留子项自己的截止时间。

“活动排列规律”在这里指作战准备、蓝图补完等类型结构，以及主活动与兑换/领取的明确关联。**列表中的第一、第二、第几张图片不作为证据。** 删除、插入和重排公告不应改变对应关系。

目前仅识别 JSON 中列出的任务动作和数量；不声称能理解全部任务、奖励或所有活动关系。不同区服关卡号等未纳入任务指纹，不能因为未建模的字段不同就声称所有任务完全相同。奖励对象少于两个、没有别名且没有足够任务证据时，日期和结构相同也不自动套图。

## 缓存、来源和启用

英文请求与所有游戏共用主程序限制器，不绕过验证码/拒绝访问；每轮最多额外 1 次目录和 6 次专题读取，图片只在本地缺失时下载。24 小时（或用户选择的 18 小时）复查及随机错峰继续生效。英文接口失败保留已缓存候选，不阻断国服日历更新。

`sources/en-artwork-live.json` 保存经过提取的候选、来源修订、日期及匹配上下文，不保存执行代码；缓存限制在插件 2 MB 读取上限以内。事件 `artwork.alignment` 和版本 `analysis.artwork_alignment` 保留结果、分数、日期偏移、任务重合及拒绝原因，便于核查。

从源码运行时，安装目录的 `rules.json` 需包含 `artwork_alignment` 引用，并放入新的 `artwork-alignment.json`。旧插件包没有这个可选字段时继续沿用原行为。主程序需重启加载新 Python 引擎；已发布 v0.1.0 不会因复制 JSON 而获得新引擎。
