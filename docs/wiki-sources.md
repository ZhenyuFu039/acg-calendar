# 明日方舟与 Wiki 数据源

## 明日方舟国服：官网优先（2026-10-27）

默认从[官网新闻目录](https://ak.hypergryph.com/news)发现最多 4 篇活动预告/寻访公告，静态读取页面中的 JSON 初始目录和公告段落，不执行网页脚本、不调用 AI、不自动请求 PRTS。按编号章节拆出活动，解析明确时间、分段开放及独立兑换期；时装、家具、礼包不作为活动导入。年份取公告发布日期，UTC+8 转 UTC 保存，未明确日期不靠活动周期猜测；只公布开始的活动保留结束待定，维护后或可能浮动的开始标为预计。预告与独立公告中名称、角色和时间区间唯一对应的条目合并；不能确定身份的条目不强行合并。

每读到一篇有效公告即保存新日期，先逐张补齐该批可确认的官方头图，再读取下一篇；整轮共用最多 16 张补图预算，不按公告次数重置。超出预算或失败的图片显示待补数量，下次同步复用已完成缓存并继续。独立寻访公告无图时保留同名、同时间范围预告中已确认的头图与原图片出处，不用空值覆盖。遵守统一限流及现有 24 小时加随机错峰的复查策略；后续公告连接失败、暂停或拒绝时停止继续请求，已保存日期和图片不回滚。单张图失败不阻断日期入库。解析范围有限，不保证覆盖新闻目录之外的旧公告、图片专属日期和所有公告格式；未识别段落显示警告。

游戏 ID、版本 ID 沿用原值。旧 PRTS 缓存及其许可继续保留；只有名称/活动类型相符且同一公告或日期重叠、候选唯一时才沿用旧活动 ID。官网日期与旧 Wiki 日期冲突时提示并采用官网；完成、收藏、备注、手动校正及计划不由采集器覆盖。详情和导出按每条活动的实际来源标注。`ArknightsCollector(source_mode='prts')` 仅保留给显式旧适配/离线测试，界面默认不启用该路径。

## 明日方舟国服：历史 PRTS 适配器

由用户指定的 [PRTS 首页](https://prts.wiki/w/首页)进入[活动一览](https://prts.wiki/w/活动一览)。这是社区维护的 Wiki，界面、导出和规则文件均与终末地的官方来源分开标注。

旧版采集流程：活动目录 → 最近 8 篇活动原文 → 最多 6 篇条目明确链接的活动公告。原文经公开 MediaWiki API 小批量读取，带 `maxlag=5`；联网仍遵守统一限流，不绕过暂停。默认同步已切换为官网，下面保留历史解析规则与署名说明。首次离线仍可使用内置真实快照。

每篇活动优先读取 `活动信息` / `活动信息/info` 模板，识别国服的活动开始、关卡结束、兑换结束、参与条件、公告链接及标题图文件名。使用模板层级解析，忽略注释，不执行模板、Widget 或网页脚本；不调用 AI。

- 国服 `cn` 字段优先，不使用日服等其他区服字段填空。
- UTC+8 时间转换为 UTC 存储，页面按所选时区与相应日期的夏令时显示。`03:59` 原样保留，不擅自改为 `04:00`。
- 关卡结束与兑换截止分别列出。没有明确兑换开始时暂沿用活动开始，但标为预计；公告明确后才确认。已明确兑换截止可以产生提醒。
- 从关联活动公告补充有明确日期范围的限时寻访，并在活动时间条中保留分阶段开放标记；不扫描整站，也不把时装、礼包等所有时间都当作活动。
- 集成战略、生息演算的常驻主条目不作为限时活动导入；独立限时任务不会仅因名字含这些词而被排除。
- 活动图片优先使用[明日方舟官网](https://ak.hypergryph.com/#information)：从活动模板的 `官网链接` ID 定位公告，一次最多 6 篇，静态读取官方图片 CDN 的横幅及其紧随章节标题。仅在活动名称明确匹配且唯一时采用；寻访须匹配自己的寻访章节，时装、礼包等图片不用于普通活动。兑换条目可共用主活动横幅，详情会明确标注。官网索引缓存 24 小时，已缓存图片无需重复下载。
- 无明确官网匹配时才尝试目录已提供、与模板文件名一致的 PRTS 媒体链接，不调用缩略图生成接口；无图或下载失败时保留颜色与完整标题。官网图片更新独立于 PRTS 日期采集，图片失败不会阻断日期保存；PRTS 不可用时也可给已有条目补充官网图片，不改变原日期及其采集时间。
- 明日方舟没有嵌晶玉列或终末地奖励小计；合并视图里的嵌晶玉列注明仅适用于终末地。

每条记录包含原页面 URL、修订 ID、固定修订 URL、字段原文及行号。同步更新不覆盖完成标记、个人提醒或时间校正；活动 ID 不依赖修订号和具体日期。

实测例子：[昨日海](https://prts.wiki/w/昨日海)的关卡结束为 2026-10-23 03:59，兑换结束为 2026-10-30 03:59（均为国服 UTC+8）；[活动公告](https://prts.wiki/w/昨日海/活动公告)另给出两批关卡开放时间及“海渊巡游”寻访。界面可查看对应固定修订，避免把查询时间或页面更新时间当成活动时间。

## 森空岛终末地 Wiki

已检查用户提供的[官方目录](https://wiki.skland.com/endfield/catalog?mainTypeId=1&subTypeId=9&filterIds=&header=0)。页面为动态加载，公开脚本中可定位到：

- `https://zonai.skland.com/web/v1/wiki/item/catalog?typeMainId=1&typeSubId=9`
- `https://zonai.skland.com/web/v1/wiki/activity`

2026-10-18（纽约时间）匿名直连实测返回 `code=10001`、`设备信息无效`。页面能打开不等于接口能被本地无账号程序稳定读取，目前不能宣称已通过森空岛采集排期。

程序仅检查公开目录的可用性，不索取账户凭证、模拟设备签名或覆盖已有排期。检查结果保存在 `source:skland`，自动启动时至多每天检查一次；状态在终末地来源栏和 `/api/state` 的 `source_checks` 中可见。即使今后接口返回成功，也先标记为需要字段映射，不未经验证直接合并。

终末地目前继续采用已验证的官方版本更新公告与版本导览；森空岛尚未参与时间或奖励统计。

## 多游戏使用与验证

网页左侧和桌面下拉框支持两款游戏及全部游戏。游戏筛选只改变显示；后台仍对两款游戏检查提醒。同名条目的 ID 含游戏维度，维护时间也只在同一游戏内关联。

时间轴左侧方块显示用户提供的游戏 APP 图标，配合各游戏的颜色边线和名称；已支持的游戏使用统一的方形圆角展示，图片铺满图标区域。活动横幅仍在时间条内渐隐显示。Windows 桌面卡片使用同样的标识与边线。

`/api/calendar.ics?game=arknights-cn` 与 `/api/export?game=arknights-cn` 只导出明日方舟；`game=all` 导出全部游戏，未知参数返回验证错误。Wiki 来源和内容许可保留在导出中。

```powershell
python -m unittest discover -s tests -p "test_*.py"
node tests/e2e.cjs
node tests/e2e-multigame.cjs
```

PRTS 编辑内容与游戏素材的许可说明见 [NOTICE](../NOTICE.md)，与本项目 MIT 代码许可分开保留。
